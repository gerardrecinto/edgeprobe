Triage a host snapshot

A snapshot is a folder of captured text: dmesg, routes, sockets, Kubernetes events, Docker rows, wireless telemetry. Pick a sample or edit the files. The real classifier runs in your browser. The samples are made-up lab data, not captures from a real host.

Rules match patterns in text, so they point at where to look. The network rule, for one, matches any default route line, which makes it a prompt to check routes and not a verdict.

How it works

Capture on the host, analyze anywhere. The analyzer never touches the machine it reports on.

1

Capture

An Ansible playbook, a Kubernetes DaemonSet or a shell script writes the snapshot files. The analyzer only reads text, so it also runs on a laptop or in CI.

2

Classify

Rules cover drivers, network path, Kubernetes, container health, GPU and CPU inventory, cellular and WiFi signal, real-time kernel stalls and build provenance.

3

Gate delivery

The exit code follows --fail-on, so a Jenkins or GitHub Actions job can stop a rollout to a node that is not ready. JSON is archived with the build.

Run it

Python 3.11 or later. Standard library only.

git clone https://github.com/gerardrecinto/edgeprobe.git
cd edgeprobe
python3 -m pip install -e .

edgeprobe analyze tests/fixtures/host-snapshot
edgeprobe analyze tests/fixtures/host-snapshot --output json
# fail the build on warnings too
edgeprobe analyze snapshot/ --fail-on warn

# without installing
PYTHONPATH=src python3 -m edgeprobe analyze snapshot/

Exit code 2 means a signal at or above --fail-on. Exit 1 means the snapshot could not be read.

What this does not do
  • It does not collect data. You supply the snapshot, and a report is only as good as what was captured.
  • Matching is by keyword and regex. A clean report does not prove a node is healthy.
  • Confidence is a formula over signal and check counts, not a probability.
  • The eBPF probe and DaemonSet in the repo are not exercised by this page.
